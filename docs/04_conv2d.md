# Conv2D: 画像処理の基本演算

GPT-2 では全結合層 (Linear) がベクトルの変換を担いました。画像を扱う SD 1.5 では、その役割を**畳み込み** (Conv2D) が担います。U-Net と VAE のほぼすべての層で使われる最も基本的な演算です。

## 1. なぜ全結合層ではなく畳み込みなのか

GPT-2 の全結合層は、各トークンの 768 次元ベクトルを別の 768 次元ベクトルに変換します（👉[GPT-2 02](https://github.com/7shi/my-gpt2/blob/main/docs/02_overview.md)）。入力の全次元が出力の全次元に接続されるため「全結合」と呼ばれます。

画像にも同じ方式を適用できるでしょうか。512×512 の RGB 画像を 1 次元に展開すると 786,432 次元になります。全結合層の重み行列は 786,432×786,432 で、float32 なら約 2.3 TB です。これは明らかに非現実的です。

畳み込みはこの問題を、**局所性**と**重み共有**の 2 つのアイデアで解決します。

- **局所性**: 各出力ピクセルは、入力の小さな領域（例: 3×3）だけを見る
- **重み共有**: 同じ 3×3 のフィルタを画像全体でスライドさせて使い回す

どちらも画像の性質に合っています。輪郭や模様といった手がかりは近くのピクセル同士の関係に現れますし（局所性）、猫の耳は画像の左上にあっても右下にあっても同じ形をしているので、場所ごとに別々の重みを用意する必要はありません（重み共有）。

3×3 フィルタで 256 チャネルから 256 チャネルへ変換する場合、重みは 256×256×3×3 = 589,824 パラメータ、float32 で約 2.4 MB です。全結合の 2.3 TB と比べて 6 桁小さくなります。しかも画像サイズに依存しないため、同じ重みを 256×256 の生成にも 512×512 の生成にも使えます。

## 2. 畳み込みの計算

入力画像の各位置で、フィルタ（**カーネル**）を重ねて要素ごとの積を取り、合計します。

3×3 カーネルによる 1 チャネルの畳み込みを例に示します。

```
入力 (4×4):          カーネル (3×3):      出力 (2×2):
┌─────────────┐      ┌─────────┐         ┌──────┐
│ 1  2  3  0  │      │ 1  0  1 │         │ 7  6 │
│ 0  1  2  1  │  *   │ 0  1  0 │    =    │ 4  5 │
│ 1  0  1  2  │      │ 1  0  1 │         └──────┘
│ 2  1  0  1  │      └─────────┘
└─────────────┘
```

左上の出力値 7 は、入力の左上 3×3 領域とカーネルの要素積の合計です。

```
1×1 + 2×0 + 3×1 +
0×0 + 1×1 + 2×0 +
1×1 + 0×0 + 1×1 = 7
```

カーネルを 1 ピクセルずつスライドさせて、すべての位置で同じ計算を繰り返します。4×4 の入力に 3×3 のカーネルを置ける位置は縦横 2 通りずつなので、出力は 2×2 になります。

### カーネルは「探したい模様」

この「要素ごとの積の合計」は、3×3 の領域とカーネルをそれぞれ 9 次元のベクトルとみなしたときの**内積**です。GPT-2 では内積を「2 つのベクトルがどれだけ似ているか」の指標として使いました。畳み込みも同じで、領域がカーネルの模様に似ているほど出力が大きくなります。

つまり、カーネルは「探したい模様」のテンプレートであり、出力は「その模様が画像のどこに、どれだけ強く現れているか」を示す地図です。上の例のカーネルは四隅と中央が 1 の「×印」なので、×印に近い領域ほど大きな値になります。どんな模様を探すか（輪郭、色の変わり目、質感など）は、学習によってカーネルの値として獲得されます。

### GPT-2 の全結合層との対応

全結合層が `y = x @ W + b` であったように、畳み込みも本質的には線形変換にバイアスを加えたものです。違いは「全次元を接続する」か「局所領域だけを接続する」かです。

## 3. 複数チャネルの畳み込み

実際の SD 1.5 では入力・出力ともに複数チャネルを持ちます。入力が $C_{in}$ チャネル、出力が $C_{out}$ チャネルの場合、カーネルの形状は ($C_{out}$, $C_{in}$, $k_H$, $k_W$) です。

```python
# weight: (C_out, C_in, kH, kW) — 例: (256, 256, 3, 3)
# bias:   (C_out,)
# input:  (C_in, H, W)
# output: (C_out, H', W')
```

**チャネル**とは、同じ空間サイズのデータを何枚も重ねたときの「枚数」の方向です。RGB 画像なら赤・緑・青の 3 チャネルですが、U-Net の内部では 320 や 1280 といった多数のチャネルを持ち、それぞれが異なる特徴（ある模様がどこにあるか）を表す地図になっています。この中間データを**特徴マップ**と呼びます。

出力の各チャネルは、入力の**全チャネル**に対してそれぞれ異なるカーネルを適用し、その結果を合計したものです。GPT-2 の全結合層で、出力の各次元が入力の全次元の重み付き和であったのと同じ構造です。空間方向は 3×3 の近傍だけを見ますが、チャネル方向は全結合になっている、と捉えることができます。

## 4. im2col による実装

素朴な多重ループ実装は極端に遅いため、**im2col** (image to column) という手法を使います。カーネルを重ねる各位置の領域（パッチ）を切り出して列として並べた行列を作り、畳み込みをカーネルとの行列積に変換します。行列積に帰着させるのは、GPT-2 の Attention で Q・K^T を `@` 演算子で一括計算したのと同じ発想です（👉[GPT-2 07](https://github.com/7shi/my-gpt2/blob/main/docs/07_attention.md)）。

先ほどの 4×4 の例では、パッチが 4 つ（出力の 2×2 に対応）あり、それぞれ 9 要素です。これを列として並べると 9×4 の行列になります。カーネルも 9 要素の行ベクトルに展開すれば、行列積 1 回で 4 つの出力がまとめて求まります。

```
col (9×4):  各列が 1 つのパッチ（3×3 を縦に展開）

         左上 右上 左下 右下
       ┌                    ┐
       │  1    2    0    1  │
       │  2    3    1    2  │
       │  3    0    2    1  │
       │  0    1    1    0  │
       │  1    2    0    1  │
       │  2    1    1    2  │
       │  1    0    2    1  │
       │  0    1    1    0  │
       │  1    2    0    1  │
       └                    ┘

kernel (1×9): [1 0 1 0 1 0 1 0 1]

kernel @ col = [7 6 4 5]  →  2×2 に reshape  →  [[7, 6], [4, 5]]
```

実装は次のとおりです。

```python
def conv2d(x, weight, bias=None, stride=1, padding=0):
    C_in, H, W = x.shape
    C_out, _, kH, kW = weight.shape
    if padding > 0:
        x = F.pad(x, (padding, padding, padding, padding))
    H_out = (H + 2 * padding - kH) // stride + 1
    W_out = (W + 2 * padding - kW) // stride + 1
    # im2col: unfold で各パッチを取り出す
    col = x.unfold(1, kH, stride).unfold(2, kW, stride)
    col = col.permute(0, 3, 4, 1, 2)          # (C_in, kH, kW, H_out, W_out)
    col = col.reshape(C_in * kH * kW, H_out * W_out)
    # カーネルを行に展開して行列積
    kernel = weight.reshape(C_out, -1)          # (C_out, C_in*kH*kW)
    out = kernel @ col                          # (C_out, H_out*W_out)
    out = out.reshape(C_out, H_out, W_out)
    if bias is not None:
        out = out + bias.reshape(-1, 1, 1)
    return out
```

`unfold` が各パッチを切り出す操作で、`permute` と `reshape` で (C_in×kH×kW, パッチ数) の行列に整えています。チャネルが複数あっても、1 つのパッチが「全チャネル分の 3×3」になって列が長くなるだけで、仕組みは同じです。

畳み込みが行列積に帰着するため、最適化された BLAS ルーチンが使え、素朴なループの数百倍の速度が得られます。

## 5. ストライドとパディング

### ストライド

カーネルをスライドさせる間隔です。`stride=2` ならば 2 ピクセルずつスライドし、出力の空間サイズが半分になります。SD 1.5 の U-Net では、ダウンサンプリングに `stride=2` の畳み込みを使います（👉[07](07_unet.md)）。

```
stride=1: 入力 4×4, カーネル 3×3 → 出力 2×2
stride=2: 入力 4×4, カーネル 3×3 → 出力 1×1
```

出力サイズの公式は次のとおりです。

$$H_{out} = \lfloor(H + 2 \times padding - k_H) / stride\rfloor + 1$$

### パディング

入力の周囲にゼロを追加して、出力サイズを調整します。

パディングなしの 3×3 畳み込みでは、先ほどの例（4×4 → 2×2）のように、カーネルがはみ出せない分だけ出力が縦横 2 ピクセルずつ縮みます。層を重ねるたびに画像が小さくなっては困るので、あらかじめ周囲を 1 ピクセル分のゼロで囲んでおきます。`padding=1` で 3×3 カーネルを使うと、入力と同じ空間サイズの出力が得られます。

```
padding=0: 入力 4×4, カーネル 3×3 → 出力 2×2
padding=1: 入力 4×4, カーネル 3×3 → 出力 4×4（6×6 に広げてから畳み込む）
```

SD 1.5 のほとんどの畳み込みは `padding=1` で空間サイズを保持します。`stride=2` と組み合わせた場合は、32×32 → 16×16 のようにちょうど半分になります。

## 実験：畳み込みの動作確認

3×3 カーネルで小さな入力画像を畳み込み、手計算の結果と一致することを確認します。また、PyTorch の `F.conv2d` と数値比較し、im2col 実装の正しさを検証します。

**実行方法**: ([04_conv2d.py](04_conv2d.py))

```bash
uv run docs/04_conv2d.py
```

```
=== 1. 手計算との比較 ===
入力:    (1, 4, 4)
カーネル: (1, 1, 3, 3)
出力:    (1, 2, 2)
出力値:
tensor([[7., 6.],
        [4., 5.]])
期待値: [[7, 6], [4, 5]]

=== 2. PyTorch との比較 ===
最大誤差: 0.0

=== 3. 複数チャネル ===
入力:    (3, 8, 8)
カーネル: (16, 3, 3, 3)
出力:    (16, 8, 8)
最大誤差: 0.00e+00

=== 4. stride=2 ===
入力:    (4, 32, 32)
出力:    (4, 16, 16) (空間サイズが半分)
最大誤差: 0.00e+00
```

手計算の結果 (7, 6, 4, 5) と一致し、PyTorch の `F.conv2d` との誤差もゼロです。複数チャネルの例では、カーネルの形状 (16, 3, 3, 3) が「出力 16 チャネル、入力 3 チャネル、3×3」を表しており、3 チャネルの入力が 16 チャネルの出力に変換されています。stride=2 の例では空間サイズが 32 → 16 と半分になっています。
