# GroupNorm: チャネル方向の正規化

GPT-2 では LayerNorm が各トークンのベクトルを平均 0・分散 1 に揃えて、後続の計算を安定させました（👉[GPT-2 06](https://github.com/7shi/my-gpt2/blob/main/docs/06_layer_norm.md)）。SD 1.5 の画像処理部（U-Net、VAE）では、同じ役割を **GroupNorm** が担います。目的は同じで、違うのは「どの範囲の値をまとめて平均・分散を計算するか」だけです。

## 1. なぜ LayerNorm ではなく GroupNorm なのか

LayerNorm は入力の**最後の次元**（GPT-2 では 768 次元）の平均と分散で正規化します。テキストのような 1 次元の系列データには適していますが、画像データには問題があります。

画像の特徴マップは `(C, H, W)` の 3 次元です。例えば `(320, 32, 32)` なら 320 チャネル、32×32 ピクセルです。これをどの範囲で正規化するかには、いくつかの選択肢があります。

- **最後の次元だけ**（LayerNorm をそのまま適用）: 横 1 列の 32 ピクセルごとに正規化することになり、行ごとに明るさが揃えられて画像の縦方向の構造が壊れてしまいます。
- **全体をまとめて**: 320 チャネルすべてを 1 つの平均・分散で正規化します。チャネルごとに値のスケールが大きく違うと、値の大きなチャネルが統計量を支配し、小さなチャネルの情報が埋もれます。
- **チャネルごとに**: 逆に細かく分けすぎると、「このチャネルは全体的に強い／弱い」という情報まで消してしまいます。

GroupNorm はこの中間を取ります。

## 2. GroupNorm の仕組み

GroupNorm は、チャネルを**グループに分けて**、各グループ内のチャネル×空間全体で正規化します。

SD 1.5 では `num_groups=32` を使います。320 チャネルなら 32 グループ×10 チャネルになり、1 グループあたり 10×32×32 = 10,240 個の値から平均と分散を計算します。

```
入力: (320, 32, 32)
  ↓ 32 グループに分割
グループ 0: チャネル 0〜9   の (10, 32, 32) → 平均・分散を計算 → 正規化
グループ 1: チャネル 10〜19 の (10, 32, 32) → 平均・分散を計算 → 正規化
  ...
グループ 31: チャネル 310〜319 の (10, 32, 32) → 平均・分散を計算 → 正規化
  ↓ チャネルごとの weight, bias でスケール・シフト
出力: (320, 32, 32)
```

各グループでは、隣り合う 10 チャネルの空間全体という十分な数の値から統計量を計算するため、安定した正規化が得られます。画像 1 枚の中だけで計算が完結するので、空間サイズが変わっても、後述するバッチサイズが変わっても、同じように動作します。

正規化の後は、LayerNorm と同じく学習済みの `weight`（γ、スケール）と `bias`（β、シフト）を適用します。これらはグループごとではなく**チャネルごと**に 1 つずつあり、正規化で揃えたスケールをチャネル単位で調整し直します。

## 3. 正規化手法の比較

| 手法 | 平均・分散を計算する範囲 | 使用場所 |
|---|---|---|
| LayerNorm | 各トークンのベクトル（768 次元）全体 | GPT-2 の各層、CLIP |
| BatchNorm | チャネルごとに、バッチ×空間 | 画像分類（ResNet 等） |
| GroupNorm | グループごとに、チャネル×空間 | SD 1.5 の U-Net、VAE |

**バッチ**とは、複数の画像をまとめて同時に処理する単位です。BatchNorm はバッチ内の他の画像も含めて統計量を計算するため、結果がバッチの内容に左右され、推論時（多くはバッチサイズ 1）には学習時に記録しておいた移動平均で代用する必要があります。GroupNorm は 1 枚の画像の中だけで計算するので、推論でも学習と同じ計算ができます。

グループ数は、両極端をつなぐツマミと考えることもできます。グループ数を 1 にすれば「全体をまとめて」正規化することになり、チャネル数と同じにすれば「チャネルごとに」正規化することになります。32 グループはその中間の設定です。

## 4. 実装

```python
def group_norm(x, weight, bias, num_groups, eps=1e-5):
    shape = x.shape
    C = shape[0]
    # チャネルをグループに分け、グループごとに 1 行に並べる
    x = x.reshape(num_groups, -1)
    # グループごとの平均と分散
    mean = x.mean(dim=1, keepdim=True)
    var = x.var(dim=1, unbiased=False, keepdim=True)
    # 平均を引いて標準偏差で割り、平均 0・分散 1 に正規化
    x = (x - mean) / torch.sqrt(var + eps)
    # 元の形状に戻す
    x = x.reshape(shape)
    # チャネルごとの weight (γ) でスケールし、bias (β) でシフト
    extra_dims = len(shape) - 1
    view_shape = (C,) + (1,) * extra_dims
    x = x * weight.reshape(view_shape) + bias.reshape(view_shape)
    return x
```

LayerNorm との核心的な違いは `reshape(num_groups, -1)` の 1 行だけです。`(320, 32, 32)` を `(32, 10240)` に変形することで、「グループごとの平均・分散」が単なる「行ごとの平均・分散」になります。それ以降の、平均を引いて標準偏差で割り、γ と β でスケール・シフトするという流れは LayerNorm と同じです。

## 実験：GroupNorm の動作確認

小さな入力で GroupNorm を計算し、PyTorch の `F.group_norm` と比較します。

**実行方法**: ([05_groupnorm.py](05_groupnorm.py))

```bash
uv run docs/05_groupnorm.py
```

```
=== 1. 基本動作 ===
入力:     (4, 3, 3)
グループ数: 2 (各グループ 2 チャネル)
最大誤差:  1.19e-07

=== 2. 正規化の効果 ===
グループ 0 正規化前: mean=-0.0392, std=1.1984
グループ 0 正規化後: mean=0.0000, std=1.0000

=== 3. SD 1.5 の典型サイズ ===
入力:     (320, 32, 32)
グループ数: 32 (各グループ 10 チャネル)
最大誤差:  1.91e-06
```

正規化後のグループ 0 は平均 0.0000、標準偏差 1.0000 になっており、正規化が正しく機能しています。SD 1.5 の典型的なサイズ (320, 32, 32) でも PyTorch との誤差は $10^{-6}$ 程度で、float32 の丸め誤差の範囲に収まっています。
