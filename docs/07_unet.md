# U-Net の全体構造

U-Net は SD 1.5 の中核をなすモデルで、パラメータの約 85% (~860M) を占めます。テキスト条件とタイムステップを受け取り、潜在表現に含まれるノイズを予測します。

## 1. U-Net とは

U-Net はもともと医療画像のセグメンテーション用に提案されたアーキテクチャで、エンコーダ（ダウンサンプリング）とデコーダ（アップサンプリング）を**スキップ接続**で結んだ U 字型の構造です。

### 設計の動機：なぜ U 字型なのか

ノイズを正しく予測するには、2 種類の情報が必要です。

- **全体の把握**: 「画面のこのあたりに猫がいる」といった構図は、広い範囲を見渡さないと分かりません。
- **細部の位置**: ノイズはピクセル単位で予測するので、「輪郭が正確にどこを通るか」という細かい位置情報も必要です。

3×3 の畳み込みが一度に見られるのは隣のピクセルまでです（👉[04](04_conv2d.md)）。しかし画像を 1/2 に縮小すれば、同じ 3×3 が元の画像の 2 倍の範囲をカバーします。縮小を繰り返して 4×4 まで小さくすれば、少ない計算で画像全体を見渡せます。これが U 字の下り（エンコーダ）です。絵を描くときに、一歩下がって全体のバランスを確認するのに似ています。

一方、縮小すると細かい位置情報は失われます。そこで U 字の上り（デコーダ）で元の大きさに戻すときに、縮小前の特徴マップを横から受け取って細部を補います。これがスキップ接続です。

全体の流れを図で示します。左側の縦の流れが U 字の下りと上りに相当し、右側の線がスキップ接続です。

```
入力 (4, 32, 32)
  ↓ conv_in
(320, 32, 32)
  ↓ Down block 0
(320, 32, 32) ──────────────────────┐ skip
  ↓ downsample (stride=2 conv)     │
(320, 16, 16)                       │
  ↓ Down block 1                    │
(640, 16, 16) ──────────────────┐   │ skip
  ↓ downsample                  │   │
(640, 8, 8)                     │   │
  ↓ Down block 2                │   │
(1280, 8, 8) ──────────────┐   │   │ skip
  ↓ downsample              │   │   │
(1280, 4, 4)                │   │   │
  ↓ Down block 3            │   │   │
(1280, 4, 4) ──────────┐   │   │   │ skip
                        │   │   │   │
  ↓ Mid block           │   │   │   │
(1280, 4, 4)            │   │   │   │
                        │   │   │   │
  ↓ Up block 0 ←───────┘   │   │   │ cat
(1280, 4, 4)                │   │   │
  ↓ upsample               │   │   │
  ↓ Up block 1 ←───────────┘   │   │ cat
(1280, 8, 8)                    │   │
  ↓ upsample                   │   │
  ↓ Up block 2 ←───────────────┘   │ cat
(640, 16, 16)                       │
  ↓ upsample                       │
  ↓ Up block 3 ←───────────────────┘ cat
(320, 32, 32)
  ↓ conv_out
出力 (4, 32, 32)
```

図では段階ごとに 1 本ずつスキップ接続を描いていますが、これは簡略化したもので、実際にはもっと多くの接続があります（3 節）。

## 2. チャネル数の変化

U-Net の各段階でチャネル数と空間サイズが変化します。下りでは空間サイズが半分になるたびにチャネル数が増えていきます。位置の細かさを減らす代わりに、各位置が持つ特徴の種類を増やしている、と捉えられます。

| 段階 | チャネル | 空間サイズ | ブロック構成 |
|---|---|---|---|
| conv_in | 4 → 320 | 32×32 | 3×3 conv |
| Down 0 | 320 | 32×32 | ResBlock×2 + Attention×2 |
| Down 1 | 320 → 640 | 16×16 | ResBlock×2 + Attention×2 |
| Down 2 | 640 → 1280 | 8×8 | ResBlock×2 + Attention×2 |
| Down 3 | 1280 | 4×4 | ResBlock×2（Attention なし） |
| Mid | 1280 | 4×4 | ResBlock + Attention + ResBlock |
| Up 0 | 1280 | 4×4 | ResBlock×3 |
| Up 1 | 1280 | 8×8 | ResBlock×3 + Attention×3 |
| Up 2 | → 640 | 16×16 | ResBlock×3 + Attention×3 |
| Up 3 | → 320 | 32×32 | ResBlock×3 + Attention×3 |
| conv_out | 320 → 4 | 32×32 | GroupNorm + SiLU + 3×3 conv |

表の「Attention」は、Self-Attention と Cross-Attention を含む SpatialTransformer のことで、次章で扱います（👉[08](08_cross_attention.md)）。

入力と出力はどちらも `(4, 32, 32)` です。入力は「ノイズを含む潜在表現」、出力は「予測されたノイズ」で、同じ形状のテンソルです。潜在表現の各要素について「このうちどれだけがノイズか」を答えるので、形状が一致します。

## 3. スキップ接続

U-Net の最大の特徴はスキップ接続です。ダウンサンプリング側の各段階の出力を保存 (`skips`) し、アップサンプリング側で `torch.cat` により**チャネル方向に結合**します。

```python
skips = [x]  # conv_in の出力

# Down blocks で skips に追加
for ...:
    x = resblock(x, temb)
    x = attention(x, context)
    skips.append(x)

# Up blocks で skips から取り出して結合
for ...:
    skip = skips.pop()          # 対応するダウン側の出力
    x = torch.cat([x, skip], dim=0)  # チャネル方向に結合
    x = resblock(x, temb)      # 結合後のチャネル数から処理
```

`skips` は後から入れたものを先に取り出すスタックです。下りの最後に保存した特徴マップが上りの最初に使われ、下りの最初に保存したものが上りの最後に使われます。これにより、同じ空間サイズの特徴マップ同士が対応します。

GPT-2 の残差接続（👉[GPT-2 09](https://github.com/7shi/my-gpt2/blob/main/docs/09_residual.md)）が `x + h` で加算だったのに対し、U-Net のスキップ接続は `torch.cat([x, skip])` で結合です。加算では 2 つの情報が混ざってしまいますが、結合なら「全体を見渡してきた情報」と「縮小前の細かい情報」が別々のチャネルとして並ぶため、次の ResBlock が両者をどう組み合わせるかを決められます。

結合によりチャネル数が増えるため（例: 1280 + 1280 = 2560）、結合直後の ResBlock は結合後のチャネル数を入力として受け取り、本来のチャネル数に戻します（👉[06](06_resblock.md) のショートカットがここで使われます）。

実際に保存される `skips` を確認すると、12 個あります。

```
skips の形状:
  [0]: (320, 32, 32)
  [1]: (320, 32, 32)
  [2]: (320, 32, 32)
  [3]: (320, 16, 16)
  [4]: (640, 16, 16)
  [5]: (640, 16, 16)
  [6]: (640, 8, 8)
  [7]: (1280, 8, 8)
  [8]: (1280, 8, 8)
  [9]: (1280, 4, 4)
  [10]: (1280, 4, 4)
  [11]: (1280, 4, 4)
```

内訳は、conv_in の出力が 1 個、各 Down block の 2 つの ResBlock（と Attention）の出力が 4 × 2 = 8 個、3 回のダウンサンプリングの出力が 3 個です。一方、4 つの Up block はそれぞれ ResBlock を 3 つ持ち、ResBlock ごとに 1 個ずつ取り出すので 4 × 3 = 12 個となり、ちょうど使い切ります。Up block の ResBlock が 3 つ（Down block より 1 つ多い）なのはこのためです。

## 4. ダウンサンプリングとアップサンプリング

### ダウンサンプリング

`stride=2` の 3×3 畳み込みで空間サイズを半分にします（👉[04](04_conv2d.md)）。

```python
x = conv2d(x, weight, bias, stride=2, padding=1)
# (C, 32, 32) → (C, 16, 16)
```

### アップサンプリング

最近傍補間で空間サイズを倍にした後、3×3 畳み込みで平滑化します。

```python
x = upsample_nearest_2d(x, 2)  # (C, 8, 8) → (C, 16, 16)
x = conv2d(x, weight, bias, padding=1)
```

`upsample_nearest_2d` は各ピクセルを 2×2 に複製するだけの単純な操作です。

```
┌──────┐      ┌────────────┐
│ a  b │      │ a  a  b  b │
│ c  d │  →   │ a  a  b  b │
└──────┘      │ c  c  d  d │
              │ c  c  d  d │
              └────────────┘
```

複製しただけではモザイクのようにカクカクするので、直後の畳み込みでなじませます。

## 5. 各ブロックの構成要素

各 Down/Up ブロックは、以下のコンポーネントの組み合わせです。

- **UNetResBlock** — 特徴量の変換 + タイムステップ埋め込み注入（👉[06](06_resblock.md)）
- **SpatialTransformer** — Self-Attention + Cross-Attention + GEGLU FFN（👉[08](08_cross_attention.md)）

U-Net が受け取る 3 つの入力が、どこから入るかを整理しておきます。

| 入力 | 入る場所 | 役割 |
|---|---|---|
| 潜在表現 (4, 32, 32) | conv_in | ノイズ除去の対象 |
| タイムステップ | すべての UNetResBlock | いまどの段階かを知らせる |
| 条件ベクトル (77, 768) | すべての SpatialTransformer | 何を描くかを知らせる |

タイムステップとテキスト条件は入口で 1 度だけ与えるのではなく、U-Net のあらゆる深さで繰り返し注入されます。

Down block 3 と Up block 0 だけは SpatialTransformer を持たず、ResBlock のみで構成されています。最も解像度が低い（4×4）段階では、空間的な Attention の効果が限定的なためです。

## 実験：U-Net の構造を追跡

U-Net の各段階でテンソル形状がどう変化するかを追跡します。`skips` の形状は本文中で引用しています。

**実行方法**: ([07_unet.py](07_unet.py))

```bash
uv run docs/07_unet.py
```

```
入力:      (4, 32, 32)
context:   (77, 768)
temb:      (1280,)

conv_in:   (320, 32, 32)
Down 0:    (320, 16, 16) (skips: 4)
Down 1:    (640, 8, 8) (skips: 7)
Down 2:    (1280, 4, 4) (skips: 10)
Down 3:    (1280, 4, 4) (skips: 12)

Mid:       (1280, 4, 4)

Up blocks のスキップ結合:
  Up 0: x (1280, 4, 4) + skip (1280, 4, 4) → cat 2560 ch

=== パラメータ数 ===
U-Net 総パラメータ: 859,520,964 (860M)
```

Down 0〜2 の形状は、各ブロック末尾のダウンサンプリングを終えた後のものです。空間サイズが 32 → 16 → 8 → 4 と半減し、チャネル数が 320 → 640 → 1280 と増加していく様子が分かります。Up block 0 の最初の ResBlock は、結合により 2560 チャネル (1280 + 1280) を入力として受け取ります。
