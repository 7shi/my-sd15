# DDIM Scheduler: ノイズ除去の数理

SD 1.5 のパイプラインでは、ランダムノイズから画像を生成するために「ノイズを少しずつ除去する」プロセスを繰り返します。この反復の各ステップを管理するのが **DDIM Scheduler** です。

U-Net が答えるのは「いまの潜在表現のうち、どれがノイズか」という予測だけです。その予測を受け取って「では潜在表現をどう更新するか」を計算するのが Scheduler の仕事です。Scheduler は学習するパラメータを持たず、数式だけで動きます。数式が続く章ですが、やっていることは「信号とノイズを決まった比率で混ぜる」「その式を逆に解く」の 2 つだけです。

## 1. 拡散モデルの考え方

拡散モデルは 2 つの過程で成り立っています。

**前方過程（学習時）**: きれいな画像にノイズを少しずつ加えて、最終的に純粋なガウスノイズにする。

```
画像 → 少しノイズ → もっとノイズ → ... → 純粋なノイズ
x_0  →    x_1    →    x_2     → ... →    x_999
```

**逆過程（推論時）**: ノイズから出発して、少しずつノイズを除去して画像を復元する。各ステップで U-Net が「どの部分がノイズか」を予測します。

```
純粋なノイズ → 少しきれい → もっときれい → ... → 画像
x_999       →    x_900   →    x_800    → ... →  x_0
```

添え字の $t$ が**タイムステップ**です。「時刻」という名前ですが、実質的には**ノイズの多さを表す目盛り**で、0 がきれいな画像、999 がほぼ純粋なノイズです。推論では大きい方から小さい方へ進みます。

推論時に行うのは逆過程だけです。前方過程は学習時にのみ使われます。学習では、きれいな画像にノイズを加えたものを U-Net に見せ、「加えたノイズを当てさせる」という問題を大量に解かせます。答えを知っている問題をいくらでも作れるのが、この方式の巧みなところです。

なお、この章では「画像」と書きますが、SD 1.5 で実際にノイズを加えたり除いたりする対象は潜在表現です。

## 2. ノイズスケジュール

前方過程の各ステップでどれだけノイズを加えるかを決めるのが**ノイズスケジュール**です。SD 1.5 は `scaled_linear` スケジュールを使います。

```python
betas = torch.linspace(0.00085 ** 0.5, 0.012 ** 0.5, 1000) ** 2
```

$\beta_t$ は各ステップのノイズ強度で、$t=0$ では小さく (0.00085) 、$t=999$ では大きく (0.012) なります。平方根の空間で線形に増加させることで、ノイズの増加を滑らかにしています。

$\beta_t$ から累積積 $\bar{\alpha}_t$ を計算します。

```python
alphas = 1.0 - betas
alphas_cumprod = torch.cumprod(alphas, dim=0)  # ᾱ_t
```

1 ステップごとに元の成分が $\alpha_t = 1 - \beta_t$ 倍に薄まっていくので、それを最初から掛け合わせた $\bar{\alpha}_t$ は「ステップ $t$ でどれだけ元の画像が残っているか」を表します。

- $t=0$: $\bar{\alpha}_0 \approx 0.999$（ほぼ元の画像）
- $t=999$: $\bar{\alpha}_{999} \approx 0.0047$（ほぼ純粋なノイズ）

前方過程は次の式で表せます。

$$x_t = \sqrt{\bar{\alpha}_t} \cdot x_0 + \sqrt{1 - \bar{\alpha}_t} \cdot \epsilon$$

ここで $\epsilon$ は標準ガウスノイズです。任意のステップ $t$ の $x_t$ を、$x_0$ と $\epsilon$ から直接計算できます（中間ステップを経由する必要がありません）。

この式が本章の中心です。意味は単純で、**$x_t$ は元の画像 $x_0$ とノイズ $\epsilon$ を決まった比率で混ぜたもの**です。$\sqrt{\bar{\alpha}_t}$ が画像（信号）の係数、$\sqrt{1 - \bar{\alpha}_t}$ がノイズの係数で、タイムステップはこの混合比を指定するツマミにあたります。

| $t$ | 信号の係数 $\sqrt{\bar{\alpha}_t}$ | ノイズの係数 $\sqrt{1-\bar{\alpha}_t}$ | 状態 |
|---:|---:|---:|---|
| 0 | 0.9996 | 0.0292 | ほぼ元の画像 |
| 100 | 0.9456 | 0.3252 | 少しノイズが乗る |
| 500 | 0.5257 | 0.8507 | ノイズの方が強い |
| 999 | 0.0683 | 0.9977 | ほぼ純粋なノイズ |

2 つの係数は 2 乗して足すと常に 1 になります。信号が減った分だけノイズが増えるので、$x_t$ 全体のスケールはどのタイムステップでもおおむね一定に保たれます。

## 3. タイムステップの選択

学習時は 1000 ステップですが、推論時は 10 ステップに間引きます。

```python
def set_timesteps(self, num_steps):
    step_ratio = 1000 / num_steps  # 100
    ts = torch.round(torch.arange(0, num_steps).float() * step_ratio).long()
    self.timesteps = ts.flip(0)  # 大→小の順
```

10 ステップの場合、タイムステップは `[900, 800, 700, 600, 500, 400, 300, 200, 100, 0]` になります。1000 段ある階段を、100 段飛ばしで降りていくイメージです。

```
 5 ステップ: [800, 600, 400, 200, 0]
10 ステップ: [900, 800, 700, 600, 500, 400, 300, 200, 100, 0]
20 ステップ: [950, 900, 850, ..., 100, 50, 0]
```

ステップ数を増やすと 1 回あたりの歩幅が小さくなり、より丁寧にノイズを除去できますが、その分だけ U-Net の実行回数が増えます。

ステップ数による生成品質の変化は以下のとおりです。これらは 10 ステップ実行の途中経過ではなく、それぞれ `steps=N` として最初から生成し直した最終画像です。

| steps=1 | steps=3 | steps=5 | steps=7 | steps=9 |
|:---:|:---:|:---:|:---:|:---:|
| ![](../steps/01-3.jpg) | ![](../steps/03-3.jpg) | ![](../steps/05-3.jpg) | ![](../steps/07-3.jpg) | ![](../steps/09-3.jpg) |

初期ステップでは $\bar{\alpha}_t$ が小さくノイズが支配的なため、U-Net は画像全体の構図や色調（低周波成分）を予測します。ステップが進み $\bar{\alpha}_t$ が大きくなると、ノイズが減って高周波成分（エッジ・テクスチャ）の予測に移ります。そのため大構造が先に決まり、細部は後から描き込まれます。各ステップの中間画像は [steps/README.md](../steps/README.md) で確認できます。

## 4. DDIM ステップ

DDIM (Denoising Diffusion Implicit Models) は、決定的 ($\eta=0$) なデノイジングステップを定義します。SD 1.5 のデフォルトスケジューラーである PNDM など他のスケジューラーでは実用的な品質を得るのに 50 ステップ程度が必要ですが、DDIM は**最低 10 ステップで形状が認識でき、実用的には 30 程度**で十分鮮明な画像が得られます。更新式もシンプルで実装が容易なため、本プロジェクトでは DDIM を採用し、時間節約のため 10 ステップを既定とします（以降の章でも DDIM を基準にします）。

各ステップで U-Net が予測したノイズ $\epsilon_\theta$ を使い、次の潜在表現を計算します。計算は 2 つの手順からなり、どちらも前方過程の式「$x_t$ = 信号 + ノイズ」を使い回すだけです。

```
x_t（t=900 の混合比）
  │  手順 1: 予測ノイズを使って分解
  ↓
x̂_0（完成画像の見積もり）と ε_θ（予測ノイズ）
  │  手順 2: t=800 の混合比で混ぜ直す
  ↓
x_{t_prev}（t=800 の混合比）
```

### 手順 1: $x_0$ の予測

U-Net の出力（予測ノイズ）から、元のきれいな画像 $x_0$ を推定します。

$$\hat{x}_0 = \frac{x_t - \sqrt{1 - \bar{\alpha}_t} \cdot \epsilon_\theta}{\sqrt{\bar{\alpha}_t}}$$

これは前方過程の式を $x_0$ について解いたものです。$x_t$ からノイズの分を引き、信号の係数で割って元のスケールに戻しています。ノイズの予測が正確なら、これだけで $x_0$ が求まることになります。

### 手順 2: 前のタイムステップへ移動

推定した $\hat{x}_0$ と予測ノイズ $\epsilon_\theta$ を使って、前のタイムステップ $t_{prev}$ の潜在表現を計算します。

$$x_{t_{prev}} = \sqrt{\bar{\alpha}_{t_{prev}}} \cdot \hat{x}_0 + \sqrt{1 - \bar{\alpha}_{t_{prev}}} \cdot \epsilon_\theta$$

こちらは前方過程の式そのもので、混合比を $t$ のものから $t_{prev}$ のものに取り替えただけです。信号の比率が少し上がり、ノイズの比率が少し下がります。

### 設計の動機：なぜ一気に $x_0$ へ進まないのか

手順 1 で $x_0$ の見積もりが得られるなら、それをそのまま完成画像にすればよさそうに思えます。そうしないのは、ノイズだらけの段階での見積もりが粗いからです。t=900 の $x_t$ では信号の係数が約 0.12 しかなく、元の画像の手がかりはほとんど残っていません。そこから言い当てられるのは、せいぜい大まかな構図や色調までです。

そこで、見積もりを信じて進むのは少しだけにします。完成画像の方向へ一歩だけ寄った（ノイズが少し減った）状態を作り、そこで改めて U-Net に予測させます。ノイズが減った分だけ次の予測は正確になり、見積もりが徐々に修正されていきます。彫刻で、いきなり細部を彫らずに、粗彫りから少しずつ形を追い込んでいくのと同じです。

### 実装

```python
def step(self, noise_pred, t, sample):
    alpha_t = self.alphas_cumprod[t]
    t_prev = t - int(self._step_ratio)
    alpha_t_prev = self.alphas_cumprod[t_prev] if t_prev >= 0 else torch.tensor(1.0)
    # x_0 の予測
    pred_x0 = (sample - torch.sqrt(1.0 - alpha_t) * noise_pred) / torch.sqrt(alpha_t)
    # 前のステップの計算
    prev_sample = torch.sqrt(alpha_t_prev) * pred_x0 + torch.sqrt(1.0 - alpha_t_prev) * noise_pred
    return prev_sample
```

$t_{prev} < 0$（最終ステップ）の場合は $\bar{\alpha}_{t_{prev}} = 1.0$ とし、$x_{t_{prev}} = \hat{x}_0$ になります。つまり最終ステップでは予測した $x_0$ がそのまま出力されます。

$\eta=0$ なので確率的なノイズ項はなく、同じ入力からは常に同じ出力が得られます。乱数を使うのは最初の初期ノイズを作るときだけで、そこから先はすべて決定的な計算です。これが同じシードで同じ画像が再現される理由です。

## 実験：DDIM Scheduler の動作確認

ノイズスケジュールの値、タイムステップの選択、前方過程の係数は本文中で引用しています。ここでは DDIM ステップの動作を確認します。

**実行方法**: ([09_ddim.py](09_ddim.py))

```bash
uv run docs/09_ddim.py
```

```
=== 4. DDIM ステップ ===
t=900 → t=800:
  入力の x_0 からの距離: 0.9200
  出力の x_0 からの距離: 0.8996

=== 5. 決定性（同じ入力 → 同じ出力）===
同じ入力での最大差: 0.00e+00
```

この実験では U-Net を使わず、人工的に作った $x_0$ にノイズ $\epsilon$ を加えて t=900 の $x_t$ を作り、「完璧なノイズ予測」として $\epsilon$ そのものを `step` に渡しています。1 ステップ進めると $x_0$ からの距離が 0.9200 → 0.8996 と縮まり、きれいな画像に一歩近づいたことが分かります（ノイズは乱数のため、値は実行ごとに多少変わります）。

完璧な予測を渡しても一気に $x_0$ にならないのは、手順 2 で t=800 相当のノイズを混ぜ直しているからです。また、同じ入力で 2 回実行した結果の差は 0 で、DDIM ステップが決定的であることも確認できます。
