# アーキテクチャ: SD 1.5 の設計思想

最終章では、SD 1.5 の全体像を振り返り、GPT-2 との構造比較を通じてアーキテクチャの設計思想を整理します。

> この章は推論パイプラインの一区間ではなく、全体を俯瞰する番外編です（03〜11 章にあるパイプライン位置リストはありません）。

## 1. パイプラインの要約

SD 1.5 の推論パイプラインは、わずか 20 行足らずのコードに集約されます。

```python
# 1. テキスト → 条件ベクトル
cond_emb = text_encoder(tokenizer.encode(prompt))        # (77, 768)
uncond_emb = text_encoder(tokenizer.encode(""))          # (77, 768)

# 2. ランダムノイズ
latents = torch.randn(4, height // 8, width // 8)        # (4, 32, 32)

# 3. デノイジングループ
for t in scheduler.timesteps:
    noise_cond = unet(latents, t, cond_emb)               # (4, 32, 32)
    noise_uncond = unet(latents, t, uncond_emb)           # (4, 32, 32)
    noise_pred = noise_uncond + cfg_scale * (noise_cond - noise_uncond)
    latents = scheduler.step(noise_pred, t, latents)      # (4, 32, 32)

# 4. 画像化
image = vae(latents / 0.18215)                            # (3, 256, 256)
```

4 つのコンポーネントが明確に分離され、それぞれが独立した役割を担っています。

| コンポーネント | 答える問い |
|---|---|
| CLIP Text Encoder | 何を描くのか |
| U-Net | いまの潜在表現の、どこがノイズか |
| Scheduler | その予測を使って、潜在表現をどう更新するか |
| VAE Decoder | 潜在表現は、ピクセルにするとどう見えるか |

コンポーネント同士は、条件ベクトル (77, 768) と潜在表現 (4, H/8, W/8) という決まった形状のデータだけでつながっています。そのため、部品を個別に差し替えることができます。スケジューラーを DDIM から LCM に、VAE Decoder を TAESD に取り替えたり（👉[10](10_vae.md)、[12](12_lora.md)）、U-Net の重みを別のモデルや LoRA で置き換えたり（👉[01](01_quickstart.md)）できたのは、この分離のおかげです。

## 2. GPT-2 との構造比較

### 共通点

| 概念 | GPT-2 | SD 1.5 |
|---|---|---|
| Attention | Self-Attention（12 ヘッド×64 次元） | Self/Cross-Attention（1 / 8 / 12 ヘッド） |
| 正規化 | LayerNorm | LayerNorm (CLIP) + GroupNorm (U-Net/VAE)  |
| 活性化関数 | GELU | SiLU (U-Net/VAE) 、Quick GELU (CLIP) 、GELU (GEGLU)  |
| 残差接続 | `x = x + f(x)` | `x = x + f(x)`（ResBlock、SpatialTransformer） |
| 埋め込み | 位置埋め込み（学習済み） | 位置埋め込み + タイムステップ埋め込み（正弦波） |
| BPE | バイトレベル BPE | バイトレベル BPE（小文字化 + `</w>`） |

### 差異

| 概念 | GPT-2 | SD 1.5 |
|---|---|---|
| 生成方式 | 自己回帰（1 トークンずつ） | 拡散（ノイズ→画像を反復） |
| 主な線形変換 | Linear（全結合） | Conv2D（畳み込み）+ Linear |
| 条件付け | なし | Cross-Attention（テキスト→画像） |
| MLP | Linear → GELU → Linear | GEGLU（ゲート付き） |
| ネットワーク構造 | 単一方向（12 層の積み重ね） | U-Net（エンコーダ・デコーダ + スキップ接続） |
| 潜在空間 | なし（トークン空間で直接） | VAE（48 倍圧縮） |
| 重みの適応 | — | [LoRA](12_lora.md)（低ランク分解で少量パラメータの追加） |

## 3. 2 種類のショートカット

SD 1.5 には、層を迂回して情報を運ぶ経路が 2 種類あります。

### ResBlock 内の残差接続

```python
return x + h   # h = GroupNorm → SiLU → Conv → GroupNorm → SiLU → Conv
```

GPT-2 の Transformer Block 内の残差接続と同じ原理です。ブロック内の変換を「修正量」として加算します。

### U-Net のスキップ接続

```python
x = torch.cat([x, skip], dim=0)  # チャネル方向に結合
```

こちらは加算ではなく**結合**です。エンコーダの高解像度な空間情報をデコーダに直接伝達します。

| | 残差接続 | スキップ接続 |
|---|---|---|
| 演算 | 加算 `x + h` | 結合 `torch.cat([x, skip])` |
| つなぐ範囲 | 1 つのブロックの入口と出口 | U 字の下りと上り（離れた層同士） |
| 役割 | 入力を保ちつつ修正を加える | 縮小で失われた細部を届ける |

ResBlock の残差接続が「局所的な情報の保存」であるのに対し、スキップ接続は「エンコーダ・デコーダ間の長距離な情報伝達」です。

## 4. Transformer の汎用性

SD 1.5 は 3 つの異なる文脈で Transformer を使っています。

| コンポーネント | 構造 | 入力 |
|---|---|---|
| CLIP Text Encoder | GPT-2 類似（因果マスク付き） | テキストトークン系列 (77, 768) |
| SpatialTransformer | Self-Attn + Cross-Attn + GEGLU | 画像特徴 (H×W, C) |
| VaeAttention | 単一ヘッド Self-Attn | 画像特徴 (H×W, C) |

核心は同じ `softmax(Q·K^T / √d)·V` の計算です。テキストに適用すれば言語モデル、画像に適用すれば画像処理、テキストと画像を結べば条件付き生成になります。Transformer の「系列に対する重み付き集約」という抽象的な操作が、さまざまなモダリティ（テキストや画像といったデータの種類）に適用できることを SD 1.5 は示しています。

畳み込みと Attention の使い分けも見えてきます。畳み込みは近傍だけを見る代わりに安価で、画像の局所的な模様を扱うのに向いています。Attention は 1 回で全体を参照できる代わりに、計算量が系列長の 2 乗に比例します。SD 1.5 の U-Net は両者を交互に重ね、局所的な処理を畳み込みに、離れた位置同士やテキストとの関係付けを Attention に任せています。

## 5. SD 1.5 からの発展

SD 1.5 以降、画像生成モデルは急速に進化しています。

### SDXL (2023)

SD 1.5 の拡張版です。U-Net のチャネル数を増やし、テキストエンコーダを 2 つ (CLIP + OpenCLIP) にして、高解像度（1024×1024）に対応しました。基本アーキテクチャは SD 1.5 と同じです。

### SD 3 / Flux (2024)

U-Net を廃止し、**DiT** (Diffusion Transformer) を採用しました。画像パッチをトークンとして扱い、テキストトークンと結合して単一の Transformer で処理します。SpatialTransformer の「画像を系列に変換する」アイデアを全面的に採用した形です。DiT の概要は次節で説明します。

### 一貫性モデル (Consistency Models) / LCM

拡散モデルの「多ステップ」という制約を取り除き、1〜2 ステップで画像を生成する手法です。DDIM の「決定的な軌跡」の考え方を発展させています。[12 章](12_lora.md)で実装した LCM LoRA は、この一貫性モデルの考え方を LoRA として既存モデルに適用したもので、U-Net 全層への LoRA 適用と専用スケジューラーの組み合わせにより 2 ステップでの生成を実現しています。

これらの発展はいずれも、SD 1.5 で学んだ概念（Attention、残差接続、潜在空間、CFG、LoRA）の延長線上にあります。SD 1.5 の理解は、最新の画像生成モデルを学ぶ確かな土台になるはずです。

## 6. DiT の概要：LLM との差分

DiT は本プロジェクトでは実装していませんが、GPT-2 を知っていれば、差分だけで概要をつかめます。DiT の本体は、GPT-2 と同じ「LayerNorm → Attention → 残差接続 → LayerNorm → MLP → 残差接続」の Transformer Block を積み重ねたものだからです。変わるのは、入口と出口、そして Attention の参照範囲です。

```
GPT-2: トークン ID 列 → WTE（表引き）→ + WPE → Block × N（因果マスクあり）→ LM Head → 次のトークン 1 個
DiT:   潜在表現 → パッチ化 → Linear → + 2 次元の位置埋め込み → Block × N（マスクなし）→ Linear → 全パッチのノイズ予測
```

DiT が置き換えるのは U-Net だけです。テキストエンコーダ、VAE、「ノイズ予測 → スケジューラーで更新」を繰り返すループは、SD 1.5 と同じ枠組みのまま残ります。

### トークンは画像のパッチ

潜在表現を 2×2 マスの小さな区画（**パッチ**）に区切り、1 つのパッチを 1 トークンとして扱います。256×256 の画像なら、潜在表現は 32×32、パッチは 16×16 = 256 個なので、系列長は 256 です。

GPT-2 のトークンは整数の ID なので、WTE の表から行を取り出してベクトルにしました。パッチは最初から数値の並び（2×2 マス × チャネル数）なので、表引きは不要で、Linear を 1 回通すだけで埋め込みベクトルになります。

### 因果マスクがない

GPT-2 は、各トークンが自分より前のトークンだけを参照するよう、因果マスクで参照範囲を制限していました。トークンを 1 つずつ順に生成するためです。

画像のパッチには生成の順序がありません。DiT は全パッチを同時に更新するので、因果マスクを使わず、**すべてのトークンが互いを参照します**。SD 1.5 の SpatialTransformer の Self-Attention と同じです（👉[08](08_cross_attention.md)）。

この違いは出力の使い方にも現れます。GPT-2 は最後の位置の出力だけを使って次のトークンを 1 個選びましたが、DiT は全位置の出力を使います。各トークンの出力ベクトルを Linear でパッチの大きさに戻して並べ直すと、入力と同じ形状のノイズ予測になります。語彙に対する確率分布を作る LM Head も、サンプリングもありません。

#### Encoder only に相当する構造

原論文の Transformer では、因果マスクのない Self-Attention を持つ側が Encoder、因果マスクを持つ側が Decoder でした。GPT-2 が Decoder only と呼ばれるのは、因果マスクを持つ側だけを残したモデルだからです。同じ基準で見ると、因果マスクのない DiT の本体は **Encoder only** に相当します。DiT は画像認識用の ViT (Vision Transformer) を土台にしており、ViT は BERT と同じ Encoder only のモデルです。

| | Self-Attention の参照範囲 | 例 |
|---|---|---|
| Encoder only | 全トークン（マスクなし） | BERT、ViT、DiT |
| Decoder only | 自分より前だけ（因果マスク） | GPT-2、現代の LLM |

ただし、構造が Encoder と同じというだけで、役割は異なります。BERT や ViT は入力を読んで表現を作るモデルですが、DiT は画像を生成する側です。因果マスクなしで生成できるのは、トークンを 1 つずつ追加する代わりに、全トークンを繰り返し更新する拡散の枠組みを使うからです。

なお、Encoder only かどうかは、Cross-Attention の有無では決まりません。次に述べるように SD 3 / Flux は Cross-Attention を使いませんが、DiT 系のモデルには、テキストを Cross-Attention で参照するもの（PixArt など）もあります。その場合も本体は因果マスクのない Block で、SD 1.5 の SpatialTransformer と同じ構成になります。

### 位置埋め込みは 2 次元の cos・sin

Attention は入力の順序に依存しないため、位置情報を明示的に与える必要があるのは GPT-2 と同じです。ただし、パッチを 1 列に並べた通し番号を位置にすると、上下に隣り合うパッチが 16 番も離れてしまい、画像の 2 次元の位置関係が伝わりません。

そこで、位置を「行」と「列」の 2 つの数で表します。それぞれを、周波数の異なる cos・sin でベクトルにして、連結します。1 次元分の計算は、タイムステップ埋め込み（👉[06](06_resblock.md)）と同じ形です。考え方を示すコードです。

```python
def sincos_1d(pos, dim):
    freqs = torch.exp(-math.log(10000) * torch.arange(dim // 2) / (dim // 2))
    args = pos * freqs
    return torch.cat([torch.sin(args), torch.cos(args)])

def sincos_2d(row, col, dim):
    # 前半の次元が行、後半の次元が列を表す
    return torch.cat([sincos_1d(row, dim // 2), sincos_1d(col, dim // 2)])
```

GPT-2 の WPE は、位置ごとのベクトルを学習した表で、1024 番目までしか持っていませんでした。計算式で作る位置埋め込みは表を持たないため、パッチの数が変わっても、つまり画像の大きさが変わっても、同じ式で求められます。

### タイムステップとテキストの与え方

U-Net と同じく、DiT にもタイムステップとテキスト条件を与える必要があります。

- **タイムステップ**: SD 1.5 と同じ cos・sin と MLP でベクトルにします。注入する場所は LayerNorm です。GPT-2 の LayerNorm は、正規化の後に適用する γ（スケール）と β（シフト）が学習済みの定数でしたが、DiT ではこれをタイムステップのベクトルから計算します。タイムステップに応じて、全トークンの特徴を一律に強めたり弱めたりする仕組みで、ResBlock でチャネルごとに加算したのと同じ役割です。
- **テキスト**: SD 3 / Flux は、テキストエンコーダの出力を画像のパッチと同じ系列に連結し、1 つの Self-Attention で処理します。画像のトークンは、ほかの画像のトークンと同じようにテキストのトークンを参照できるので、Cross-Attention という別の層は不要になります。テキストを読む CLIP や T5 は別のモデルとして残りますが、その出力は読まれるだけでなく、Block を通るたびに画像のトークンと一緒に更新されます。Encoder の出力を固定して Decoder が参照する形（👉[08](08_cross_attention.md)）とは異なり、プロンプトと生成中の内容が 1 つの系列に並ぶ点は、LLM に近い形です。

### まとめ

| | GPT-2 | DiT |
|---|---|---|
| トークン | テキストの断片（整数 ID） | 潜在表現のパッチ（数値の並び） |
| 入力の埋め込み | WTE の表引き | Linear |
| 位置埋め込み | 学習済みの表（1 次元） | cos・sin の計算式（2 次元） |
| Attention の参照範囲 | 自分より前だけ（因果マスク） | 全トークン（マスクなし） |
| 原論文の構造との対応 | Decoder only | Encoder only |
| LayerNorm の γ・β | 学習済みの定数 | タイムステップから計算 |
| 出力 | 最後の位置から、次のトークンの確率分布 | 全位置から、パッチごとのノイズ予測 |
| ループ | トークンを 1 つずつ追加 | 同じ系列全体を繰り返し更新 |

ここで説明したのは基本形です。実際のモデルには、位置情報を RoPE（回転による位置埋め込み）で与えるもの（Flux）や、ノイズの代わりに「ノイズから画像へ向かう方向」を予測するもの（SD 3 / Flux）など、さまざまな改良があります。それでも、GPT-2 で学んだ Transformer Block と、SD 1.5 で学んだ拡散の枠組みを組み合わせたもの、という見取り図は変わりません。
